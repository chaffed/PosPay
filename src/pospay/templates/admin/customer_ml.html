Each network can score this customer's exceptions with either the bank-wide global model or a model trained only on this customer's own decision history. "Auto" (the default) uses this customer's own model automatically once one has been trained and activated, and falls back to the global model until then — no action needed. "Always global" and "Always this customer" override that: pin scoring to one source regardless of what's available. Retraining and activating below work exactly like the bank-wide models on the main ML Models page, just scoped to this one customer.

Default disposition decides what happens to an exception if no one responds within its response window: "None" (default) leaves it open indefinitely; "Always pay"/ "Always return" apply a fixed outcome; "ML-determined" re-scores the exception at the deadline and picks pay/return from the model's own probability. An ACH return (fixed or ML-determined) needs a return reason from this tenant's own catalog — if none is configured, that customer+ACH auto-decisioning is skipped rather than guessed, and retried on the next sweep.
