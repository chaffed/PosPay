ML Scoring & Default Disposition

Two related settings, both configured per customer and per payment network (check and ACH separately): how confident the fraud model needs to be before a score is shown, and what should happen automatically if nobody responds to an exception in time.

{{ docs.screenshot("admin_ml_models", "ML models admin screen") }}

ML scoring mode

From Admin, open a customer's ML settings to choose its scoring mode for each network. Models can also be retrained and, once ready, activated — either for a single customer or, for the shared baseline model, tenant-wide.

Default disposition

Set what happens when an exception's response window closes with no human decision: a fixed pay or return outcome, or let the ML model's score decide. You also configure the response window itself (in hours) and, for ACH, the default return reason to use. If ML-determined disposition is selected but there isn't yet enough model data to score an item, it's skipped rather than guessed — it stays open for a human to review rather than risk an under-informed automatic decision.

A scheduled sweep applies these defaults to any exception whose window has expired; decisions it makes are marked as automatic in the audit log and exception history, so they're always distinguishable from a human's decision.
